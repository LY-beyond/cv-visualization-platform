# 平台改进方案（借鉴 CVClass 参考站）

> 依据 `reference/CVClass` 的产品形态与工程实现，结合本平台现有 React + FastAPI 架构，给出可落地的改进设计。
> 文档中的复杂度标记：**S** 小、**M** 中、**L** 大；不包含工期估算。

## 1. 结论摘要

参考站的优势在“学习引导、逐步演示、真实推理、教学辅助”，本平台的优势在“案例契约、真实训练评估、章节内容完整、离线可演示”。改进应围绕四个关键词展开：

1. **串起来**：把 37 个案例组织成学习路径与知识图谱，而不是平铺在章节页。
2. **动起来**：用统一播放器把后端已有的 `steps` 变成可播放的实验过程。
3. **真起来**：用浏览器端 ONNX 推理替换检测/分割的示例结果。
4. **讲起来**：用离线规则诊断 + 可选大模型，让每个案例都能“解释—诊断—总结”。

## 2. 现状与差距

| 能力 | 本平台现状 | 参考站做法 | 差距 |
| --- | --- | --- | --- |
| 章节组织 | 7 章 + 37 案例，按课程顺序 | 4 大学习世界、40+ 页面、World/Level 闯关 | 缺少学习路径与前置关系 |
| 知识关联 | 第 1 章有发展时间线 | 可缩放拖拽的知识图谱 | 缺少跨章节知识网络 |
| 分步演示 | `CaseOutput.steps` 静态列表 | 时间轴 + 播放/暂停/速度 + 步骤讲解 | 已有数据，缺播放器 |
| 真实模型 | 检测/分割以示例与经典算法为主 | YOLO11n、SegFormer 在浏览器 ONNX 运行 | 缺真实深度模型 |
| 教学辅助 | 无 | AI 助手：解释、参数分析、结果诊断、讲解稿 | 从零开始，可先做规则版 |
| 实验页骨架 | 参数面板 + 结果区 + 步骤 | 左参数/原理，右画布/当前计算/公式 | 缺“当前计算式 + 诊断” |
| 算法透明性 | OpenCV / sklearn 为主 | NumPy 手写 + numba 加速 | 缺“手写步骤”视图 |
| 内容广度 | 覆盖第 1~6 章 | 含几何、双目、光流、姿态、ViT/CLIP、生成式 | ch7~ch9 可扩展 |
| 工程架构 | 组件化 + 注册表 + 测试 | 67 个模板、逐页 JS，重复度高 | 本平台架构更优，无需照搬 |

## 3. 总体改进蓝图

```text
数据层
├── chapters/config.ts           章节讲解、公式、对比表、结构图（已有）
├── chapters/learningPath.ts     学习世界 → 关卡 → 前置关系 → 案例引用（新增）
├── cases/guidance.ts            每个案例的原理、公式、诊断提示（新增）
└── inference/modelConfig.ts     浏览器推理模型配置（新增）

组件层
├── viz/StepPlayer.tsx           通用步骤播放器（新增）
├── viz/Formula.tsx              KaTeX 公式渲染（新增）
├── assistant/AssistantPanel.tsx AI 助手抽屉（新增）
├── assistant/rules.ts           离线诊断规则（新增）
└── pages/GraphView.tsx          ECharts 知识图谱（新增）

页面层
├── /                首页：四大学习域 + 进度概览（改造）
├── /path            学习路径闯关地图（新增）
├── /graph           知识图谱（新增）
├── /chapters/:id    章节页：讲解 + 案例工作台（已有，补锚点与诊断）
└── /chapters/:id#case-xxx  案例锚点直达（新增）
```

改进遵循两条原则：

- **不破坏现有契约**：后端 `CaseOutput` 与案例注册机制保持不变，新增能力优先在前端组合。
- **离线优先**：所有新增能力必须有本地降级路径，大模型、ONNX 模型都作为可选增强。

## 4. P0 改进项

### 4.1 P0-1 学习路径地图与知识图谱

**目标**：把章节和案例组织成“可导航、可追踪、可讲解”的学习网络。

**4.1.1 数据模型**（新增 `frontend/src/chapters/learningPath.ts`）

```ts
export interface LearningCaseRef {
  chapterId: string;
  caseId: string;
  label?: string; // 路径卡片上展示的案例名，缺省取案例元信息
}

export interface LearningLevel {
  id: string;
  title: string;
  summary: string;
  task: string;        // 本关要完成的任务
  input: string;       // 输入
  output: string;      // 输出
  core: string[];      // 核心计算步骤
  concepts: string[];  // 关键概念
  metrics: string[];   // 观察指标
  prerequisites: string[]; // 前置关卡 id
  cases: LearningCaseRef[];
}

export interface LearningWorld {
  id: string;
  title: string;
  description: string;
  levels: LearningLevel[];
}
```

建议划分为四个学习世界，与课件主线一致：

| 学习世界 | 关卡示例 | 关联章节 |
| --- | --- | --- |
| 基础视觉 | 颜色与通道、卷积与池化、LBP/SIFT/HOG、拼接与 RANSAC | ch2、ch2-stitch |
| 深度视觉 | BoW 分类、LeNet/AlexNet、训练与评估、特征嵌入 | ch3 |
| 识别与分割 | K-Means/边缘分割、FCN/DeepLab、检测基础、YOLO | ch4、ch5 |
| 识别与前沿 | 指纹与虹膜、人脸识别、跟踪/多目/VQA（规划） | ch6、ch7~ch9 |

**4.1.2 学习路径页**（新增 `frontend/src/pages/LearningPathPage.tsx`，路由 `/path`）

- 顶部：总体进度条、完成关卡数、继续学习按钮（跳转最近访问案例）。
- 主体：按学习世界分组的关卡卡片，展示任务、核心计算、指标与前置关卡。
- 关卡状态：未开始 / 进行中 / 已完成，依据本地进度记录计算。
- 点击关卡：右侧抽屉展示完整信息，并提供“进入实验”按钮，跳到
  `/chapters/{chapterId}#case-{caseId}`。
- 前置未完成时给出提示，但不强制锁定，保证答辩演示自由跳转。

**4.1.3 知识图谱**（新增 `frontend/src/pages/GraphView.tsx`，路由 `/graph`）

- 数据来源：章节配置 + 学习路径 + 案例元信息，节点分为“章节 / 关卡 / 案例”三类。
- 边：`章节 → 案例`（包含关系）、`关卡 → 案例`（教学关系）、`关卡 → 关卡`（前置关系）。
- ECharts `graph` 实现：
  - `layout: "force"` 或预计算坐标；`roam: true` 支持缩放拖拽；
  - 按学习世界着色，节点大小按关联度；
  - 点击案例节点跳转章节锚点，点击关卡节点打开路径抽屉；
  - 提供“回到根节点 / 全量视图 / 仅看当前章节”三个操作。
- 低端设备降级：节点数超过 60 时默认只显示章节与关卡，案例节点按需展开。

**4.1.4 进度记录**（新增 `frontend/src/stores/progressStore.ts`）

```ts
// localStorage key: cvp:progress:v1
interface ProgressState {
  visitedCases: string[];      // 打开过并执行成功的案例 id
  completedLevels: string[];   // 关联案例全部访问过的关卡
  lastCase?: { chapterId: string; caseId: string; at: number };
}
```

- 案例执行成功时写入 `visitedCases`；关卡下所有案例访问后自动完成。
- 首页与学习路径读取进度，展示百分比与徽章；提供“重置进度”入口。
- 单机演示场景不引入后端进度表，避免多用户与鉴权复杂度。

**4.1.5 章节锚点**

- `CaseWorkbench` 外层容器增加 `id={"case-" + meta.id}`。
- `ChapterPage` 监听 `location.hash`，页面加载后滚动到对应案例并高亮 1.5 秒。
- 解决 React Router 不会自动滚动锚点的问题。

**涉及文件**：`chapters/learningPath.ts`、`pages/LearningPathPage.tsx`、`pages/GraphView.tsx`、`stores/progressStore.ts`、`App.tsx`、`components/Layout.tsx`、`components/HomePage.tsx`、`cases/CaseWorkbench.tsx`、`components/ChapterPage.tsx`。

**验收标准**：

- `/path` 可看到 4 个学习世界及全部关卡，进度随案例访问实时变化。
- `/graph` 支持缩放拖拽，点击案例节点可定位到对应章节案例。
- 刷新后进度不丢失；重置后归零。
- 学习路径中引用的案例 id 全部存在（运行时过滤未知 id 并告警）。

### 4.2 P0-2 统一步骤播放器

**目标**：让后端案例已有的 `steps` 从静态列表升级为可播放、可讲解的实验过程。

**4.2.1 组件设计**（新增 `frontend/src/viz/StepPlayer.tsx`）

```ts
interface StepPlayerProps {
  steps: { title: string; description: string; image?: string }[];
  autoPlay?: boolean;      // 默认 false，章节内手动播放
  interval?: number;       // 默认 1800ms
  showImages?: boolean;    // 默认 true
}
```

功能：

- 播放 / 暂停、上一步 / 下一步、进度条与步骤计数。
- 速度切换 0.5× / 1× / 2×。
- 当前步骤高亮，说明文字与步骤图片同步展示。
- 键盘操作：空格播放/暂停，左右方向键切换步骤。
- 自动播放到最后一步停止；组件卸载时清理定时器。
- 尊重 `prefers-reduced-motion`：减少动画时不自动播放，仅静态展示。
- 暗色模式沿用现有 Tailwind 变量。

**4.2.2 接入 CaseResult**

- 将 [CaseResult.tsx](file:///d:/Visualization_Platform/cv-visualization-platform/frontend/src/cases/CaseResult.tsx) 中的静态步骤列表替换为 `StepPlayer`。
- 保留“查看全部步骤”折叠视图，便于快速浏览。
- 当前步骤的 `description` 同时作为 P1-2“当前计算式”卡片的内容来源，避免重复维护。
- 前端案例（BoW 动画、训练曲线回放）可复用同一播放器，逐步统一交互语言。

**4.2.3 后端可选增强**

`CaseOutput.steps` 结构保持兼容，可增加可选字段：

```python
class CaseStep(BaseModel):
    title: str
    description: str
    image: str | None = None
    formula: str | None = None   # 新增：该步对应的计算式/公式
```

`formula` 用于实验页“当前计算式”卡片；未提供时回退到步骤说明。

**涉及文件**：`viz/StepPlayer.tsx`（新增）、`cases/CaseResult.tsx`、`schemas/case.py`、`cases/*.py`（按需补 formula）。

**验收标准**：

- 任意后端案例的结果区可播放 / 暂停 / 调速 / 前后切换。
- 步骤图片与说明同步，播放结束自动停止。
- 页面切换或案例切换时无定时器泄漏与状态串扰。
- 移动端控件可点按，不与页面滚动冲突。

### 4.3 P0-3 浏览器端真实推理（检测 / 分割）

**目标**：用真实深度模型替换第 4/5 章的示例结果，提升“真实感”与答辩说服力。

**4.3.1 依赖与资源**

- 新增依赖：`onnxruntime-web`。
- 模型目录：

```text
frontend/public/models/
├── manifest.json                 # 可选模型清单与体积、是否已下载
├── detection/
│   ├── yolov8n.onnx
│   ├── labels.json
│   └── config.json
└── segmentation/
    ├── segformer.onnx
    ├── labels.json
    └── config.json
```

**4.3.2 配置模型**（新增 `frontend/src/inference/modelConfig.ts`）

```ts
export interface OrtModelConfig {
  id: string;
  task: "detection" | "segmentation";
  modelPath: string;      // /models/detection/yolov8n.onnx
  labelsPath: string;
  inputSize: [number, number];
  layout: "NCHW";
  mean: number[];
  std: number[];
  scoreThreshold: number;
  iouThreshold: number;
  palette?: string[];     // 分割配色
}
```

配置文件由前端 fetch 读取，与参考站“每个模型一份 JSON”的做法一致。

**4.3.3 推理管线**（新增 `frontend/src/inference/`）

- `ort.ts`：初始化 `ort.env.wasm.wasmPaths` 指向本地目录，优先 WebGPU，失败回退 WASM。
- `inference.worker.ts`：在 Web Worker 中执行推理，避免阻塞 UI；主线程只传图像 ImageData 与配置。
- 预处理：letterbox 缩放、归一化、NCHW 转换；记录缩放比例与 padding。
- 检测后处理：输出框还原到原图坐标、置信度过滤、类别 NMS、绘制框与标签。
- 分割后处理：逐像素 argmax → 调色板着色 → 与原图按透明度叠加。
- 步骤输出：预处理、推理、后处理、叠加四个步骤，可直接交给 `StepPlayer`。

**4.3.4 案例接入**

- 新增 `frontend/src/cases/frontend/OnnxCases.tsx`：
  - `onnx_detect`：上传/选择示例图 → 推理 → 检测框叠加 + 类别统计柱状图；
  - `onnx_segment`：示例图 → 推理 → 掩码叠加 + 类别像素占比。
- 在 `cases/registry.tsx` 注册；在 `builtin.py` 增加对应案例元信息（`implementation: "frontend"`），前端注册后自动接管。
- **契约说明**：浏览器推理案例由前端直接渲染结果，仍复用 `CaseFrame` 与 `CaseResult` 的图片/指标/步骤展示组件；后端 `CaseOutput` 契约继续服务后端案例，不强行让后端参与推理。
- **降级策略**：启动时检查 `manifest.json`；模型缺失或加载失败时，展示原示例案例并提示“未检测到本地模型，已使用内置示例”。保证断网、无模型时仍可演示。

**4.3.5 风险控制**

- 模型体积：检测模型建议 ≤ 15MB，分割模型建议 ≤ 30MB；只保留一份量化版本。
- 兼容性：WebGPU 不可用时回退 WASM；Safari 低版本提示升级。
- 许可：模型与权重需确认可再分发，必要时在文档中标注来源与许可证。
- 首屏性能：模型延迟加载，仅进入对应案例时下载与初始化。

**涉及文件**：`package.json`、`inference/{modelConfig,ort,worker}.ts`、`cases/frontend/OnnxCases.tsx`、`cases/registry.tsx`、`backend/app/cases/builtin.py`、`public/models/*`、`docs/部署说明.md`。

**验收标准**：

- 断网环境下，检测/分割案例可完成真实推理并叠加结果。
- 推理过程中页面不卡顿（Worker），单张图片推理可接受。
- 模型缺失时自动回退示例，不出现白屏或报错。
- 结果图、类别统计与步骤播放一致。

## 5. P1 改进项

### 5.1 P1-1 AI 学习助手（离线规则优先）

**目标**：为当前案例提供“解释算法、分析参数、诊断结果、生成讲解稿”能力，且不破坏离线演示。

**5.1.1 上下文采集**（新增 `frontend/src/assistant/context.ts`）

```ts
interface AssistantContext {
  chapterId: string;
  chapterTitle: string;
  caseId?: string;
  caseName?: string;
  params: Record<string, unknown>;
  metrics: Record<string, string>;
  steps: { title: string; description: string }[];
  resultSummary: { images: number; charts: number };
}
```

参数来自 `ParamPanel` 的受控值，指标与步骤来自最近一次案例结果，无需后端改造。

**5.1.2 离线规则引擎**（新增 `frontend/src/assistant/rules.ts`）

- 通用规则：
  - 结果为空：提示检查输入、阈值与参数范围；
  - 步骤过少：提示参数可能导致流程提前结束；
  - 图片/图表缺失：提示后端案例是否已实现。
- 案例专属规则（按 `caseId` 注册）：
  - `detect_overlay`：置信度阈值过低导致误检多、IoU 阈值过高抑制不足；
  - `kmeans_seg`：k 过大导致碎片化、迭代次数不足导致未收敛；
  - `canny_steps`：双阈值比例失衡导致边缘断裂或噪声过多；
  - `model_compare`：准确率差距、最低召回类别；
  - `feature_embedding`：t-SNE 聚类是否分离、PCA 是否线性展开。
- 输出四类内容：算法解释、参数分析、结果诊断、讲解稿（可直接复制）。
- 每条建议附带依据（使用了哪个参数、哪个指标），避免空泛表述。

**5.1.3 UI**（新增 `frontend/src/assistant/AssistantPanel.tsx`）

- 右下角悬浮按钮，点击打开抽屉；展示当前章节/案例上下文摘要。
- 四个快捷动作按钮 + 自由提问输入框。
- 结果以 Markdown 渲染，支持复制讲解稿。
- 无网络时仅启用规则动作，联网大模型作为可选增强。

**5.1.4 可选联网接口**（新增 `backend/app/api/assistant.py`）

```text
POST /api/assistant/chat
{
  "question": "...",
  "action": "explain | analyze | diagnose | script",
  "context": { ...AssistantContext }
}
→ SSE 流式返回
```

- 通过环境变量 `ASSISTANT_BASE_URL`、`ASSISTANT_API_KEY`、`ASSISTANT_MODEL` 控制；
- 未配置时接口返回 503 并提示“未启用在线助手”，前端自动回退规则引擎；
- 请求体做长度与字段校验，避免把整页内容或敏感信息发给外部服务。

**涉及文件**：`assistant/{context,rules,AssistantPanel}.tsx`、`App`/`Layout` 挂载、`api/client.ts`、`backend/app/api/assistant.py`、`api/__init__.py`、`docs/部署说明.md`。

**验收标准**：

- 任一后端案例结果出来后，助手能给出至少 1 条与参数/指标相关的具体诊断。
- 离线状态下规则功能完整可用；未配置 Key 时在线接口优雅降级。
- 生成的讲解稿可复制，内容与当前案例一致。

### 5.2 P1-2 实验页信息骨架

**目标**：把每个案例从“结果展示”升级为“实验台”：参数、原理、当前计算、结果诊断四段齐全。

**5.2.1 案例教学元信息**（新增 `frontend/src/cases/guidance.ts`）

```ts
  pitfalls?: string[];     // 常见误区
}

export const caseGuidance: Record<string, CaseGuidance> = {
  channel_viewer: { /* ... */ },
  canny_steps: { /* ... */ },
  // 按案例 id 维护

```

放在前端维护的好处：不改后端 schema，迭代快；待内容稳定后可迁移到 `CaseMeta`。

**5.2.2 CaseFrame 左侧信息区**

### 5.3 P1-3 算法透明性（NumPy 手写视图）

**目标**：为核心算法提供“库实现 / 手写步骤”双视图，解释算法内部计算过程。

**5.3.1 后端新模块**（新增 `backend/app/algorithms/numpy_ops.py`）

```python
def grayscale(image: np.ndarray, weights=(0.299, 0.587, 0.114)) -> np.ndarray: ...
def convolve2d(image, kernel, stride=1, padding=0) -> tuple[np.ndarray, list[dict]]: ...
def otsu_threshold(gray) -> tuple[int, list[dict]]: ...
def kmeans_pixels(pixels, k, max_iter, seed=0) -> tuple[np.ndarray, list[dict]]: ...
def canny_steps(gray, low, high) -> dict[str, np.ndarray]: ...
```

- 每一步返回中间结果与说明，直接映射为 `CaseOutput.steps`。
- 性能敏感函数可选用 numba；未安装时回退纯 NumPy。
- 图像尺寸与迭代次数设上限，避免课堂演示卡顿。

**5.3.2 案例参数扩展**

为 `conv_slide`、`threshold_compare`、`kmeans_seg`、`canny_steps` 增加：

```text
engine: select ["opencv", "numpy"]  默认 opencv
```

- `opencv` 保持现有结果与性能；
- `numpy` 输出逐窗口/逐迭代的中间图与计算说明；
- 两种模式共享同一套参数与结果展示。

**5.3.3 测试**

- 新增 `backend/tests/test_numpy_ops.py`：
  - 与 OpenCV 结果对比（灰度、Otsu 阈值、卷积），允许数值容差；
  - K-Means 在固定随机种子下结果稳定；
  - 中间步骤数量与尺寸正确。
- 现有案例契约测试保持通过。

**涉及文件**：`backend/app/algorithms/numpy_ops.py`、`cases/ch2_basic.py`、`cases/ch4_seg.py`、`cases/builtin.py`、`backend/tests/test_numpy_ops.py`。

**验收标准**：

- 同一参数下两种引擎结果视觉一致（允许 ±1 灰度误差）。
- 手写模式能看到卷积窗口、Otsu 类间方差、K-Means 迭代等中间结果。
- 默认仍为 OpenCV，性能不受影响。

## 10. 风险与降级

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| ONNX 模型体积过大 | 首屏与仓库膨胀 | 延迟加载、量化模型、manifest 标记可选资源 |
| WebGPU 兼容性不足 | 推理失败 | 自动回退 WASM；加载失败回退示例案例 |
| 知识图谱节点过多 | 低端设备卡顿 | 默认分层展示，按需展开案例节点 |
| 学习路径与案例 id 漂移 | 跳转失效 | 运行时校验 + 构建脚本告警 |
| 在线助手依赖外部 Key | 断网不可用 | 规则引擎为默认能力，在线功能显式开关 |
| NumPy 手写性能不足 | 演示卡顿 | 限制尺寸与迭代次数，必要时启用 numba |
| 新增页面破坏现有路由 | 原有链接失效 | 仅新增路由，不改现有路径；`/app` 基路径已适配 |
