## 3. 阶段一：基础设施与最小闭环

### 3.1 任务清单

| 编号 | 任务 | 涉及位置 | 交付物 |
| --- | --- | --- | --- |
| A1 | 准备 MNIST 小样本与清单 | `backend/storage/datasets/mnist_subset/` | 每类 20~50 张图 + `manifest.json` |
| A2 | 实现数据集训练/测试划分读取 | `app/datasets/base.py` | 统一 `samples(split)` 返回样本与标签 |
| A3 | 实现 LeNet-5 Handler | `app/models/lenet5.py` | 构建、训练、推理、评估、特征提取 |
| A4 | 以 PyTorch 实现训练循环与逐轮指标 | `app/trainer/` | 每轮 loss/acc/val 指标回调 |
| A5 | 训练结果落盘与缓存 | `app/trainer/history.py` | `results/<task_id>/history.json`、`evaluation.json` |
| A6 | 前端训练面板 | `src/chapters`、`src/components` | 选择数据集/模型/超参，创建任务并订阅 SSE |
| A7 | SSE 前端接入 | `src/api/client.ts`、`src/stores/taskStore.ts` | 曲线与日志实时增量更新 |
| A8 | 错误样例与混淆矩阵展示 | `src/viz/` | 热力图 + 错误样本画廊 |

### 3.2 关键实现约定

- **样本格式**：`storage/datasets/<id>/manifest.json` 中 `splits.train/test` 均为 `{path,label}` 数组；图片相对数据集目录。
- **训练上限**：轮次不超过 `TRAIN_MAX_EPOCHS`（20），样本不超过 `TRAIN_MAX_SAMPLES`（5000），超时 300 秒。
- **事件协议**：沿用 `log / metric / state / done / error` 五类事件，消息体含 `task_id`、`epoch`、指标与时间戳。
- **缓存策略**：同一数据集 + 模型 + 超参组合命中已有结果时直接复用，界面标注“来自缓存”。

### 3.3 验收标准

- [ ] 新数据集仅新增目录与 `manifest.json` 即出现在前端下拉框。
- [ ] LeNet-5 在 MNIST 小样本上完成训练，SSE 曲线连续更新。
- [ ] 训练结束后返回 Top-1 准确率、混淆矩阵与至少 8 张错误样例。
- [ ] 训练中途失败或超时有明确错误信息，服务不崩溃。
- [ ] 断网状态下可回放已保存的历史曲线。

| 案例 | 实现方式 | 后端接口/算法 | 前端呈现 |

| 案例 | 实现方式 | 后端接口/算法 | 前端呈现 |

### 5.6 通用接入步骤

1. 在 `app/cases/` 新建案例实现，继承 `BaseCase`，实现 `execute`。
2. 将 `meta.implemented` 改为 `True`，补齐 `params` 与结果字段。
3. 前端纯前端案例在 `src/cases/registry.tsx` 注册组件。
4. 使用统一输出结构：`images / overlay / charts / steps / metrics`。
5. 每个案例准备固定示例输入，作为答辩兜底。

## 7. 技术实施要点

### 7.1 扩展方式

- **新增数据集**：`app/datasets/` 实现契约 → 注册表登记 → `storage/datasets/<id>/` 放样本。
- **新增模型**：`app/models/` 实现 Handler → 登记元信息与超参 → 前端自动生成卡片。
- **新增案例**：`app/cases/` 实现 `BaseCase` → 置 `implemented=True`；纯前端在 `src/cases/registry.tsx` 登记。
- **新增章节**：修改 `src/chapters/config.ts`，套用三段式模板。

### 7.2 性能与降级

- 现场训练仅限浅层模型与小样本，统一轮次/时长/样本上限。
- 复杂模型只做预训练推理与历史回放，提供“预训练演示”标识。
- 图表数据量大时降采样，SSE 保持每轮一次指标推送。
- 所有关键结果保留离线副本，训练失败可回退。

### 7.3 接口契约

- 数据集/模型列表字段保持稳定，新增字段向后兼容追加。
- 训练请求：`model_id + dataset_id + hyperparams`，返回 `task_id`。
- 案例请求：`params + image + dataset_id + sample_index`，返回结构化可视化数据。
- 错误统一为 `{code, message, data}`，禁用无提示的空白页面。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| CPU 训练深度模型过慢 | 演示卡顿 | 复杂模型一律预训练；现场训练仅浅层模型并设上限 |
| 课件结构图为位图、清晰度不足 | 讲解页观感差 | 提前提取归档，必要时矢量重绘 |
| 前后端字段不一致 | 联调返工 | 先冻结 `CaseOutput` / `TrainEvent` 契约，再并行开发 |
| 案例数量多、周期紧张 | 无法全部完成 | 按章节核心度排序，每章先保 3 个核心案例 |
| 答辩环境断网或性能波动 | 演示失败 | 权重、素材、结果全部离线缓存，准备固定示例输入 |
| 范围膨胀 | 主线延期 | 第 7/8/9 章仅留占位，不投入实现 |

## 10. 近期执行顺序（建议）

1. **先修数据与最小模型**：补齐 MNIST 小样本，完成 LeNet-5 Handler，打通训练—SSE—评估闭环。
2. **再补分类章模型**：K-Means、SVM、BoW，接入模型对比与嵌入投影。
3. **随后按章推进案例**：第 2 章基础 → 第 2 章拼接 → 第 4 章分割 → 第 5 章检测 → 第 6 章识别。
4. **最后统一打磨**：文案、素材、主题、离线兜底、测试与答辩材料。

> 每个阶段结束执行一次“新增内容不改框架”的回归检查，确保注册制与统一契约始终成立。
