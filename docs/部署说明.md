# 部署说明

本文档覆盖开发调试、离线单机部署、数据准备与常见问题。

## 1. 环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| Python | 3.10+ | 后端运行环境，仓库内含 `backend/.venv` |
| Node.js | 18+ | 前端开发与构建 |
| 操作系统 | Windows / Linux / macOS | 命令以 Windows PowerShell 为例 |

离线机器需提前准备好 Python 依赖与 `frontend/node_modules`（或构建好的 `frontend/dist`）。

## 2. 目录约定

```text
backend/
├── .venv/                 # Python 虚拟环境
├── app/                   # 后端应用
├── pretrain/              # 预训练权重与训练历史
├── storage/
│   ├── datasets/          # 内置数据集（含 manifest.json）
│   ├── assets/            # 案例示意图与课件结构图（/assets 静态访问）
│   └── results/           # 训练评估与案例结果缓存
├── tests/                 # 回归测试
└── requirements.txt

frontend/
├── src/                   # 前端源码
├── public/models/         # 浏览器推理模型、标签、ORT 运行时
├── dist/                  # 生产构建产物（npm run build 生成）
└── package.json
```

## 3. 首次安装

### 3.1 后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

如虚拟环境已存在，直接激活即可。Linux/macOS 使用 `source .venv/bin/activate`。

### 3.2 数据集

仓库内置 `mnist_subset` 小样本。若目录为空，可离线重新生成：

```powershell
cd backend
.\.venv\Scripts\python.exe scripts\prepare_datasets.py
```

### 3.3 前端

```powershell
cd frontend
npm install
```

## 4. 开发模式

两个终端分别启动：

```powershell
# 终端 1：后端（8000）
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# 终端 2：前端（5173）
cd frontend
npm run dev
```

访问 http://localhost:5173 。开发服务器已将 `/api`、`/assets` 代理到 8000 端口。

- 接口文档：http://127.0.0.1:8000/docs
- 健康检查：http://127.0.0.1:8000/api/health

## 5. 离线单机部署（推荐答辩使用）

前端构建产物由后端统一托管，只需一个进程：

```powershell
# 1. 构建前端（生产模式自动使用 /app 作为基础路径）
cd frontend
npm run build

# 2. 启动后端
cd ..\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

访问 http://127.0.0.1:8000/app/ 。

- 若 `frontend/dist` 不存在，`/app` 会返回 404 并提示先执行构建。
- 后端已对前端路由做回退处理，直接访问 `/app/chapters/ch3`、`/app/path`、`/app/graph` 可正常打开。
- 课件结构图通过 `/assets/course/...` 提供，与前端部署路径互不影响。
- 学习进度保存在浏览器 `localStorage` 的 `cvp:progress:v1`，清除站点数据即可重置。

> 也可以使用 Nginx 等静态服务器托管 `frontend/dist`，将 `/api` 与 `/assets` 反向代理到后端 8000 端口；需要注意构建时把 `vite.config.ts` 的 `base` 调整为根路径。

### 5.1 浏览器端 ONNX 模型（可选）

第 4/5 章的浏览器推理案例默认读取 `frontend/public/models/manifest.json`。将模型放到对应目录即可启用真实推理：

```text
frontend/public/models/
├── detection/     model.onnx + config.json + labels.json
├── segmentation/  model.onnx + config.json + labels.json
└── ort/           ort-wasm-simd-threaded.wasm / .mjs
```

构建后这些文件会原样复制到 `frontend/dist/models/`。未提供模型时页面会提示并自动回退到后端示例结果，不影响答辩演示。模型与配置字段说明见根目录 README。

## 6. 离线演练检查清单

答辩前建议依次确认：

1. 断开外网后打开首页，章节导航与首页内容正常显示。
2. 打开学习路径（`/app/path`）与知识图谱（`/app/graph`），关卡与边可点击直达案例。
3. 第 2 章进入“通道查看”“LBP 编码演示”，拖动参数后结果实时更新。
4. 第 2 章实例进入“拼接结果展示”，能看到匹配与拼接图片。
5. 第 3 章“模型对比面板”显示 4 个模型的准确率柱状图与混淆矩阵。
6. 第 3 章“特征嵌入投影”默认 t-SNE 出图，切换 PCA 后散点重新渲染。
7. 第 4 章“K-Means 分割迭代”切换“NumPy 手写步骤”，确认指标与中间帧正常。
8. 第 4/5 章打开浏览器推理案例，无模型文件时应自动回退并给出提示。
9. 第 7/8/9 章各打开一个案例，确认有图、有指标、有步骤回放。
10. 查看章节页核心公式为 KaTeX 排版；切换深色模式，公式与图表文字仍清晰可读。
11. 右下角离线助教可解释当前案例并给出结果诊断。

## 7. 测试

后端回归测试（案例契约、注册一致性、离线素材、NumPy 算子）：

```powershell
cd backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

NumPy 算子单独运行：

```powershell
cd backend
.\.venv\Scripts\python.exe -m unittest tests.test_numpy_ops -v
```

前端类型检查与构建：

```powershell
cd frontend
npm run build
```

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 端口 8000 被占用 | `Get-NetTCPConnection -LocalPort 8000` 找到进程后结束，或改用 `--port 8001`（前端代理需同步修改） |
| 端口 5173 被占用 | Vite 会自动尝试下一个端口，以终端输出为准 |
| `/app/` 返回 404 | 未构建前端，先在 `frontend` 执行 `npm run build` |
| 案例提示“示例数据” | 该数据集尚无真实训练评估，属于预期兜底；训练一次后刷新即可 |
| 特征嵌入首次较慢 | t-SNE 首次计算约 1~2 秒，属正常耗时 |
| 结构图不显示 | 确认 `backend/storage/assets/course/` 下的图片存在，并重启后端 |
| 训练任务显示中断 | 服务重启会中断后台训练线程，历史任务会被标记为失败，重新发起即可 |
| 浏览器推理提示“未找到模型” | 属于预期降级；按 5.1 放置 `model.onnx` 后重启构建即可启用 |
| 学习进度未保存 | 进度依赖浏览器 `localStorage`，无痕模式或清除站点数据后会重置 |
| 中文乱码（终端） | 属于 PowerShell 控制台编码显示问题，不影响接口与页面内容 |

## 9. 数据维护

- 训练结果：按任务存放在 `backend/storage/results/<task_id>/`，包含 `task.json`、`evaluation.json` 与 `history.json`。删除对应目录即可清理，但需重启后端以刷新内存中的任务列表。
- 数据集：`backend/storage/datasets/<dataset_id>/` 与 `manifest.json` 一一对应，替换样本后保持路径与标签一致即可。
- 预置结果：答辩机器可提前训练并保留 `storage/results`，第 3 章将直接读取真实评估结果。
